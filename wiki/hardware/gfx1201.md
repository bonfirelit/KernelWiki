# gfx1201 (RDNA4) as a kernel target

The RDNA4 discrete target: `amdgcn-amd-amdhsa--gfx1201`. Everything a kernel
author has to hold in mind that differs from a CDNA part is on this page; the
per-feature detail lives in `hw-wmma-rdna4`, `hw-lds`, and `hw-amd-memory-ops`.

## Shape of the machine

| Property | Value | How to read it |
|---|---|---|
| Wavefront | 32 lanes | Not 64. Every wave-level reduction, ballot, and lane-index derivation differs from CDNA. |
| `multiProcessorCount` (HIP) | 32 | HIP counts **WGPs**, not CUs. |
| Compute Units (`rocminfo`) | 64 | Two CUs per WGP; 2 SIMDs per CU; 4 shader engines. |
| LDS | 64 KiB per workgroup and per CU | A quarter of CDNA4's 160 KiB. Budget accordingly. |
| Max waves per CU | 32 | 2048 max threads per WGP. |
| VGPR file | 196608 registers per block | |
| L2 | 8 MiB | |

The HIP-vs-`rocminfo` count is the first thing that trips people: an occupancy
calculation keyed on `multiProcessorCount` is counting WGPs, and a grid sized
"one workgroup per CU" from that number launches half as many as intended.

## Matrix core

WMMA, not MFMA — see `hw-wmma-rdna4`. There is no MFMA instruction, no AGPR
file, and no `global_load_lds` direct-to-LDS path on this target; the CDNA
kernel idioms that depend on them do not port. `migration-cdna-to-rdna4`
enumerates the gap.

## Verified on this host

Two gfx1201 devices, 32 GiB each, ROCm 7.2 (`hipconfig --version` reports
`7.2.53211`), max clock 2350 MHz.

The `hw-wmma-rdna4` fragment-layout snippet was compiled with
`hipcc --offload-arch=gfx1201` and run against a CPU reference GEMM on this
host: **0 of 256 accumulator elements mismatched**, confirming both the
published lane mapping and the A-is-column-major convention on real silicon.

```bash
# Reproduce the device inventory the table above is drawn from.
rocminfo | grep -A24 'Name:  *gfx1201'
hipcc --offload-arch=gfx1201 props.hip -o props && ./props
```

Note: `/dev/kfd` is `root:render` 0660 and group membership is fixed at login,
so a process started before the user joined `render` reports "No HIP GPUs are
available" even though the driver is healthy. Run under `sg render -c '...'`.
